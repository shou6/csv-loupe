# 拡張機能のアイコンの作成

ユーザーが用意した元の画像（手書き、AI が生成したもの、ラフ）を元に、公開できるアイコンに仕上げる。
仕上げたアイコンは、リポジトリのスクリプトでいつでも作り直せる形にするのが基本。

## 1. 条件を確かめる

| 条件 | 内容 |
| --- | --- |
| 形式 | Marketplace は 128px 以上の正方形の PNG。SVG は不可。256px で作る |
| 置き場所 | `package.json` の `icon`（例：`resources/icon.png`）。`files` の許可リストに含める |
| 小さい表示 | 拡張機能ビューでは 32px 前後になる。細い線や小さい文字は潰れる |

## 2. ブランドの制約を確かめる

元の画像に他社のロゴが入っていないかを最初に見る。AI が生成した画像には入りやすい。

- **VS Code のロゴは使えない**。[ブランドガイドライン](https://code.visualstudio.com/brand)が次を禁じている
  - 自分の拡張機能やサービスを示すために使う
  - 描き直す、画像や文字を重ねる、変形するなどの加工
- 依存先の拡張機能のロゴやアイコンをそのまま使うのも避ける（別のものだと分かる図案にする）

問題があれば、使える部分だけを残して描き直す案を出す。AI に図案を頼み直す時は、この条件を最初に伝えてもらう。

## 3. Pillow で下書きする

図案を素早く試すには Python の Pillow を使う（`python -c "import PIL"` で有無を確かめる）。
`assets/draft-icon.py` は下書きの例。次の描き方をしている。

- 1024px で描いて 256px に縮小する（縁がなめらかになる）
- 角丸の背景、縦のグラデーション、ぼかした影、角を折った書類、丸いバッジ

下書きはスクラッチパッドに置き、`assets/preview-icon.py` で確認用の画像を作ってユーザーに見せる。

```bash
python assets/preview-icon.py icon-draft.png icon-preview.png
```

確認用の画像は、256px・128px・32px を明るい背景と暗い背景の両方に並べる。32px で形が分かるかを必ず見る。
ユーザーが IDE で開けるよう、見せる画像はリポジトリ内の git 管理外の場所（例：`docs/`）にもコピーする。

## 4. リポジトリのスクリプトに移す

図案が決まったら、画像ライブラリに依存しない Node のスクリプトに移し、`npm run icon` で作り直せるようにする。
`assets/generate-icon.js` がその実装で、`scripts/generate-icon.js` に置いて使う。

描画の仕組み。

- 図形は符号付き距離（内側が負）で判定する：角丸の四角、円。三角形は辺の向きで判定する
- `colorAt(x, y)` の中で、奥の層から順に `paint(色, 透明度)` で重ねる
- 影は、図形までの距離から透明度を求める（ガウスぼかしの近似）
- 1 画素を 4 x 4 に分けて塗り、透明度を掛けた値で平均する（縁が暗くにじまない）
- 座標は 1024 の下書きの単位で書き、`UNIT` で出力の大きさに縮める。Pillow の下書きの座標をそのまま使える
- PNG は Node 標準の `zlib` と自前の CRC32 で書き出す

移したら、Pillow の下書きと見比べる。

```bash
python -c "from PIL import Image, ImageChops; a=Image.open('resources/icon.png').convert('RGBA'); b=Image.open('icon-draft.png').convert('RGBA'); print(max(x[1] for x in ImageChops.difference(a,b).getextrema()))"
```

差の最大値が数十程度なら、影の縁の近似の差なので問題ない。目でも見比べる。

## 5. 仕上げ

- 単体テストがあれば、アイコンの条件（128px 以上の正方形の PNG、`files` に含まれる）を検査する
- VSIX を作り、アイコンが入ることを確かめる（`npm run vsix`）
- 下書きや確認用の画像は消す。ユーザーが置いた元の画像は消さない
- スクリプトの先頭のコメントに図案の意味を書く。色は定数にまとめ、直す場所を分かりやすくする
